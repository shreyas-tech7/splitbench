# Decisions

One line for each choice: the options weighed and the reason.

| Date | Decision | Options weighed | Reason |
| --- | --- | --- | --- |
| 2026-11-23 | Name `splitbench` | splitbench, solocrew, agentsplit | pypi.org and registry.npmjs.org both answered 404 for `splitbench` on 2026-11-23, and it matches the repo name |
| 2026-11-23 | Push to `claude/project-thread-mok4pw`, not `claude/build-splitbench` | the brief's branch name, the branch the session allows | The session's git rules allow only `claude/project-thread-mok4pw`. Earlier Set 2 builds used their session branch too |
| 2026-11-23 | JSON actions in plain text for every model | native tool calling, JSON in text | Works the same on any free model and on the scripted model. The brief names it as the fallback for unreliable tool calling, so it is the default from the start |
| 2026-11-23 | 58 companies, 5 documents each, plus 6 sector directories and 5 city registers (301 documents) | 300 company documents with no index, directories that list document ids | Directories let a breadth task start from one read, the way a real index works. Each fact sits in one self-contained sentence, so one parser reads documents, notes and reports |
| 2026-11-23 | Search returns ids and titles only, no snippet | snippets with text, titles only | A snippet would often hold the answer, and then reading would cost nothing. Titles force a `read_doc` per fact |
| 2026-11-23 | The scripted model reasons perfectly over what is visible in its own context | a noisy scripted model, a perfect one | Noise would be a number I invent. A perfect reasoner makes every difference come from what reaches each agent's context and what each protocol costs in tokens. The README says that no LLM ran |
| 2026-11-23 | Budget currency is the harness count (one token per 4 characters) of the exact prompt and output | provider-reported usage, harness count | The harness count is known before a call, so a reservation can guarantee the cap. Provider usage is logged next to it in record mode |
| 2026-11-23 | Reserve before each call, grant at most what is left | check after the call | A check after the call lets the last call or parallel workers pass the cap. `tests/test_budget.py` fails with that version |
| 2026-11-23 | Every prompt ends with "Budget left: N tokens, M tool calls" | hide the budget, show it | Agents can only stop and answer with what they have if they can see the budget. Every role sees the same line |
| 2026-11-23 | The orchestrator gives each worker an equal child budget and keeps 20% for its final call | one shared pool, equal shares | With one pool the workers can spend everything and the lead cannot combine. A reserve is part of a sane lead design |
| 2026-11-23 | The pipeline executor gets 65% of what is left after the planner, the checker the rest | equal thirds, executor first | The executor does the reading. The checker needs room to reread facts that the evidence lost |
| 2026-11-23 | The scratchpad agent keeps only its last 2 turns plus the scratchpad | keep the full history and add notes, trim history | Notes on top of the full history only add tokens. The test is whether memory alone can replace history |
| 2026-11-23 | The lead splits a sector or city among 3 to 5 workers (one per 3 companies) and sends a chain to one worker | split chains by hop, one worker per chain | A chain's later hops depend on earlier ones, so parallel workers cannot start them |
| 2026-11-23 | Max output 512 tokens per call for every role | provider default, 512 | A common setting. It also makes long reports and long evidence get cut, which is a real handoff risk |
| 2026-11-23 | Budget levels: tight 10,000 tokens and 20 tool calls, loose 45,000 tokens and 40 tool calls | levels from dev, levels from held-out | Set on the 20 dev tasks only, with no cap: the median run of all four designs used 10,377 tokens and 12.5 tool calls, and the largest used 43,525 tokens and 31 calls. Tight sits at the median, loose just above the largest dev run |
| 2026-11-23 | Time is reported as model calls on the critical path, not seconds | seconds of the scripted run, modeled latency, critical-path calls | Scripted calls take microseconds, and a latency model would invent constants. The critical path counts the calls that must happen one after another (parallel workers count as the slowest one) |
| 2026-11-23 | Intervals: Wilson for success, paired bootstrap over tasks for differences (2,000 resamples, seeds 0 to 2) | normal approximation, Wilson and bootstrap | The scripted model has no sampling noise, so the intervals describe task sampling only. The README says so |
| 2026-11-23 | MAST tags by six fixed rules in `metrics.mast_tag` | a judge model, rules | Exact rules keep the score free of judges. Each failed run gets one group |
| 2026-11-23 | Handoff loss: needed facts that an upstream agent saw in a tool result but that were missing from the final agent's context when it answered | count all facts, count only needed facts | Only needed facts change the answer. A second number, `dropped`, counts facts missing from the handoff messages even when the final agent found them again |
| 2026-11-23 | Skill installs skipped | `npx skills add`, git clone of the skill | The permission system denied `npx skills add`. The prompt says not to try the same step in another form. The superpowers skills were already in the session, and ponytail rules were followed by hand |
